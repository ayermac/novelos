## 0. 执行摘要

本次审计揭示了三个与原计划假设**显著不同**的关键事实，它们**大幅降低**了 v6.10.18 的实施风险：

1. **真实字段数为 23，非计划所称的 24**（7 Tier1 + 16 Tier2）。计划文档自身的字段枚举也存在 7+16=23 的内部不一致。
2. **存在两个截然不同的 `ChapterBrief` 类**（`chapter_contracts.py` 嵌套式 + `schemas.py` 扁平式），字段集、类型、默认值均已漂移。这是 v6.10.18 必须先解决的**前置架构问题**，否则"简化 ChapterBrief"目标不明确。
3. **skills 子系统对 ChapterBrief 字段零引用**（27 个 skill 文件，所有 23 字段 `grep` 计数为 0）。原计划列为"#1 风险"的"Skill 高依赖"**基本不成立**--skills 读取的是 payload（`content`/`text`/`plot_holes`/`instruction`/`genre_contract`/`foreshadowing`），与字段同名仅是概念重叠。

frontend 同样几乎不直接引用这些字段名（quoted-key 计数全为 0，属性访问仅 `ending_hook` 出现 2 次），耦合度远低于计划 7.1 节的评估。

**结论**：v6.10.18 的字段弃用可在**比原计划低得多的风险**下推进，但应优先处理两个 `ChapterBrief` 类的归一化。

## 1. ChapterBrief 模型定义核查（源头真相）

代码库中存在**两个**同名 `ChapterBrief` 类：

### 1.1 `novel_factory/models/chapter_contracts.py:51`

嵌套结构，23 字段：

```python
class ChapterBriefTier1(BaseModel):   # 7 字段
    chapter_goal, reader_payoff, protagonist_agency, forbidden_moves,
    core_loop_target, primary_payoff, payoff_evidence_plan

class ChapterBriefTier2(BaseModel):   # 16 字段
    pressure_budget, payoff_budget, upgrade_or_skill_use, character_arc_moves,
    mystery_actions, conflict_actions, ledger_debts_to_pay, new_debts_allowed,
    scene_count_target, opening_hook, ending_hook, quality_threshold_overrides,
    supporting_mechanisms_used, new_mechanisms_allowed, drift_risks, contract_checklist

class ChapterBrief(BaseModel):
    tier1: ChapterBriefTier1
    tier2: ChapterBriefTier2
```

**使用方**：`quality/core_loop_checker.py`、`workflow/nodes/__init__.py`，以及 rhythm_budget / core_loop 相关测试。

### 1.2 `novel_factory/models/schemas.py:36`

扁平结构，**字段集不同**，且与 1.1 存在**类型/默认值冲突**：

```python
class ChapterBrief(BaseModel):
    # 传统字段（向后兼容）
    objective, required_events, plots_to_plant, plots_to_resolve,
    ending_hook, constraints
    # Tier 1
    chapter_goal, reader_payoff, protagonist_agency, forbidden_moves
    # Tier 2（注意：缺 primary_payoff / payoff_evidence_plan /
    #   supporting_mechanisms_used / new_mechanisms_allowed / drift_risks / contract_checklist）
    pressure_budget, payoff_budget, upgrade_or_skill_use, character_arc_moves,
    mystery_actions, conflict_actions, ledger_debts_to_pay,
    new_debts_allowed,   # ⚠ bool = True（1.1 中为 list[str]）
    scene_count_target,  # ⚠ 默认 3（1.1 中默认 0）
    opening_hook, quality_threshold_overrides
    # v6.10.9
    core_loop, dialogue_target_ratio, fact_locks
```

**使用方**：`PlannerOutput.chapter_brief`（Planner 实际输出），`agents/screenwriter.py`、`agents/author/__init__.py`、`agent_runtime/context_builder.py`、`api/routes/chapter_briefs.py`、`models/outputs.py`、`quality/chapter_brief_validator.py`。

### 1.3 冲突汇总

| 字段 | chapter_contracts.py | schemas.py | 冲突 |
|------|---------------------|------------|------|
| `new_debts_allowed` | `list[str]` | `bool = True` | **类型冲突** |
| `scene_count_target` | `int = 0` | `int = 3` | **默认值冲突** |
| `primary_payoff` / `payoff_evidence_plan` | 存在（Tier1） | **缺失** | 字段集漂移 |
| `supporting_mechanisms_used` / `new_mechanisms_allowed` / `drift_risks` / `contract_checklist` | 存在（Tier2） | **缺失** | 字段集漂移 |
| `objective` / `required_events` / `plots_to_plant` / `plots_to_resolve` / `constraints` / `core_loop` / `dialogue_target_ratio` / `fact_locks` | **缺失** | 存在 | 字段集漂移 |

> **建议**：v6.10.18 阶段 1 必须先判定哪个类为权威，并归一化。`schemas.py` 版本是 Planner 实际产出且被 agent/API 消费，是事实上的主版本；`chapter_contracts.py` 版本仅被 quality 子集使用。归一化方向建议以 `schemas.py` 为基线收编 `chapter_contracts.py`，或反向，需在阶段 1 决策。

## 3. Skill 依赖审计（交叉核实）

- `novel_factory/skills/` 共 **27 个** `.py` 文件（与计划一致）。
- **所有 23 字段在 skills 层 quoted-key 计数均为 0**；对 7 个高风险字段属性访问抽样亦全为 0。
- 抽查关键 skill（与字段名概念重叠者）：
  - `foreshadowing_debt_skill.py`：**不读** `ledger_debts_to_pay`，读 `payload.plot_holes`/`instruction`/`used_plot_refs`/`content`（伏笔/plot 债务，非契约 ledger 债务）。
  - `opening_hook_checker.py`：**不读** `opening_hook` 字段，分析 `payload.text`/`content` 的章首钩子模式。
  - `commercial_viability_checker.py`：`_check_opening_hook`/`_check_protagonist_agency` 是方法名，分析 `content`，非字段。
  - `mystery_integrity_checker.py`：**不读** `mystery_actions`，读 `content`/`genre_contract`/`foreshadowing`。

**结论**：skill 子系统通过 payload（章节正文 + 上下文）运作，与 ChapterBrief 字段**无数据依赖**。计划 §8 所列"Skill 高依赖"风险**不成立**。详细逐 skill 表见 `v6.10.18-skill-dependency-audit.md`。

## 4. 前端耦合审计

- 23 字段在 `frontend/src/` 的 quoted-key 计数**全为 0**；属性访问抽样仅 `.ending_hook` = 2。
- `frontend/src/` 对 `tier1`/`tier2`/`ChapterBrief`/`chapter_goal`/`forbidden_moves` **零引用**。
- API 层（`api/routes/chapter_briefs.py:78`）将 DB `instruction.objective` 映射为扁平 `chapter_goal` 返回前端，但前端不直接消费这些字段名。

**结论**：frontend 与 ChapterBrief 字段耦合**极低**。计划 §7.1 所列受影响组件（CreativeContractsModule、GenesisModule 等）的实际字段引用需在阶段 1 逐组件复核，但整体前端改造工作量远低于计划估计。

## 6. 修订后的字段处置清单（v6.10.18 仅标记 deprecated）

v6.10.18 **不删除任何字段/列**，仅标记 deprecated + 保留兼容。基于审计，处置清单修订如下：

### 6.1 保留（核心，不弃用）
- `chapter_goal`、`forbidden_moves`、`ending_hook`

### 6.2 标记 deprecated（v6.10.18），v6.10.19+ 移除/合并
- **低引用，可安全弃用**（backend=0）：`core_loop_target`、`primary_payoff`、`payoff_evidence_plan`、`supporting_mechanisms_used`、`new_mechanisms_allowed`、`drift_risks`、`contract_checklist`
- **中低引用，弃用并合并到 `notes`/`payoff_points`/`conflict`**：`reader_payoff`、`protagonist_agency`、`pressure_budget`、`payoff_budget`、`upgrade_or_skill_use`、`character_arc_moves`、`mystery_actions`、`conflict_actions`、`ledger_debts_to_pay`、`new_debts_allowed`、`scene_count_target`、`opening_hook`、`quality_threshold_overrides`

### 6.3 前置阻断项（必须在阶段 1 解决）
- **两个 `ChapterBrief` 类归一化**（§1.3）：`new_debts_allowed` 类型冲突、`scene_count_target` 默认值冲突、字段集漂移。在归一化前，不得对 `new_debts_allowed`/`scene_count_target` 等冲突字段单独操作。
