# v5.6 Author Workbench 完成报告

## 总结

v5.6 Phase 1 已经把项目页从偏“生产控制台”的形态，调整为默认进入个人创作工作台。当前项目页的核心结构是：

```text
项目菜单 + 章节导航 + 写作区 + AI Agent 面板
```

这个版本是 WebUI 和交互层里程碑，不改变后端工作流契约，也不改变 v5.5.15 的生产防护逻辑。

## 初版后的关键修复

### 1. 恢复缺失的项目菜单

第一版工作台过度强调章节导航，导致一些项目资料入口变得不够明显。v5.6 现在保留工作台为默认入口，同时恢复这些模块的可达性：

- 工作台
- 写章节
- 审稿发布
- 记忆收件箱
- 创世设定
- 大纲篇章
- 章节指令
- 人物
- 势力
- 世界资料
- 伏笔
- 事实账本
- 风格规范
- 系统状态

### 2. 修复章节菜单目标错误

章节操作菜单现在会明确作用于被点击的章节，不再因为闭包拿到当前选中章节而误操作其他章节。

### 3. 保留 v5.5.15 防护语义

v5.5.15 的 guard 行为保持不变：

- running workflow 阻止重复生成；
- 终态章节不显示危险的生成入口；
- `reviewed + real mode` 显示发布；
- `published` 显示继续下一章；
- `auto_generate=1` 继续遵守 guard 条件。

### 4. 暴露卡住工作流恢复入口

当工作流疑似卡住时，工作台现在会直接提供恢复动作，而不是只提示某个节点已经运行很久。

### 5. 修正工作流时间线文案

UI 不再把 `screenwriter` 显示成“策划”。节点映射调整为：

| 内部步骤 | UI 展示 |
| --- | --- |
| `planner` | 规划 |
| `screenwriter` | 编剧 |
| `author` | 执笔 |
| `polisher` | 润色 |
| `editor` | 审核 |
| `publisher` / `awaiting_publish` | 发布 |

## 当前状态

v5.6 Phase 1 已经完成，可以作为当前 WebUI 工作台基线。项目现在是在 v5.5.15 生产防护基线之上，具备了一个可用的个人创作工作台。

剩余视觉和体验打磨应作为下一阶段 UX refinement，而不是继续阻塞本里程碑。下一步更高价值的方向是让工作台真正支撑日常写作：正文编辑、保存、版本对比、局部返修、运行恢复信心、记忆/上下文可见性，以及导出发布流程。
