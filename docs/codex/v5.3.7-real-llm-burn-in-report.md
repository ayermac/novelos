## 5. Failures Found & Fixed

### Fix 1: SSE `run_complete` missing `run_id`
**Symptom:** Stream endpoint returned `"run_id": ""` in `run_complete` event.

**Root cause:** `runner.py` skipped `health_check` node events with `continue`,
which also skipped the `state.update(node_output)` merge that persists
`workflow_run_id` into the local `state` variable.

**Fix:** Moved `state.update(node_output)` **before** the `continue` for internal
nodes so all state mutations are preserved regardless of SSE emission.

**File:** `novel_factory/workflow/runner.py`

### Fix 2: style-bible-checker silently skipped
**Symptom:** `skill_runs` table empty for chapter 9; style-bible-checker always
returned `"note": "No Style Bible provided, skipping check"`.

**Root cause:** `editor.py` passed `payload={"text": content, "chapter_number": n}`
to `run_skills_for_agent()` but never included `style_bible`. The skill's
`run()` method requires `payload["style_bible"]` to perform checks.

**Fix:** Editor now loads `style_bible` via `repo.get_style_bible(project_id)`
and injects it into the skill payload when available. Gracefully continues
without it when no style bible exists.

**File:** `novel_factory/agents/editor.py`

## 9. Recommendations

1. **Monitor token costs** — real-mode chapter generation consumes ~32K tokens
   per run (including revisions). Consider cost alerts for production.
2. **Style bible seeding** — projects created before v4.0 may lack style_bibles.
   Consider an onboarding step or auto-generation stub.
3. **Memory curator coverage** — burn-in did not hit the memory curator path
   because editor failed. A future burn-in should include an editor-passing
   chapter to validate end-to-end memory extraction + batch apply.
4. **Migration drift guard** — acceptance DB had migrations 024/025 unapplied.
   Add a startup health check that warns if `_migrations_applied` is behind
   `migrations/` directory count.
