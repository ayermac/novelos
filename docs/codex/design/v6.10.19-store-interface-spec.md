# v6.10.19 Store 接口设计规格

> 版本: v6.10.19 Phase 1
> 状态: Draft (完善版，基于真实 Repository 方法签名)
> 日期: 2026-07-09

## 0. 设计目标

在现有 Repository facade 之上增加 8 个聚合 Store（Facade 模式），提供跨 Repository 的聚合查询。不删除任何 Repository，双轨并存。

### 关键架构事实（修正 Draft v1）

`novel_factory/db/repository.py` 的 `Repository` 类是**单 facade 类**，通过多继承组合了全部领域 mixin（WorkflowRepositoryMixin、ChapterRepositoryMixin 等约 28 个 mixin）。构造方式：`Repository(db_path)` 或 `Repository()`，实例即含全部领域方法。

**因此 Store 不需要管理多个 repo 实例**。Store 直接持有单个 `Repository` 实例，调用其方法即可。Draft v1 的 `_get_repo(repo_class)` 分发设计**不适用**（mixin 不可独立实例化）。

### 原则
- Store 是聚合层，持有单个 `Repository` 实例
- Store 只做查询聚合，不做写入（写入仍走 Repository）
- 每个 Store 实现后需性能基准测试（N+1 风险评估）
- 双轨并存：现有调用方继续用 Repository，新代码可用 Store

## 1. BaseStore 接口（修正）

```python
# novel_factory/stores/base.py

from __future__ import annotations
from typing import Any
from ..db.repository import Repository


class BaseStore:
    """Store 基类 - 持有单个 Repository facade 实例，提供聚合查询。

    与 Draft v1 的差异：Repository 是单 facade 类（含全部 mixin），
    Store 直接调用 self._repo.<method>()，无需 _get_repo 分发。
    """

    def __init__(self, repo: Repository | None = None) -> None:
        """
        Args:
            repo: 已实例化的 Repository。若 None 则新建 Repository()。
        """
        self._repo = repo if repo is not None else Repository()

    @property
    def repo(self) -> Repository:
        """暴露底层 Repository，供需要写入或细粒度查询的调用方使用。"""
        return self._repo
```

### 设计要点
- **连接管理**：Repository 内部通过 `_conn()` -> `get_connection(db_path)` 管理连接，Store 不介入连接层
- **事务边界**：Store 聚合查询是只读的，不跨 repo 协调事务；写入仍由调用方通过 `store.repo` 直接操作
- **零破坏**：Store 是新增层，不修改 Repository 任何方法

## 2. Phase A 首批 3 个 Store（基于真实方法签名）

### 2.1 ProgressStore（聚合 workflow + execution_event）

底层方法（已确认签名）：
- `repo.get_workflow_runs_for_project(project_id, chapter_number=None, limit=...)` -> list[dict]
- `repo.recover_active_workflow_runs_for_chapter(project_id, chapter_number)` -> list[dict]
- `repo.count_recent_failed_workflow_runs(project_id, chapter_number, since=None)` -> int
- `repo.get_chapter_retry_count(project_id, chapter_number)` -> int
- `repo.get_chapter_total_retry_count(project_id, chapter_number)` -> int
- `repo.get_latest_chapter_reset_marker(project_id, chapter_number)` -> str | None
- `repo.get_project_workflow_token_total(project_id)` -> int
- `repo.get_workflow_execution_events(project_id, ...)` -> list[dict]
- `repo.get_workflow_execution_events_for_chapter(project_id, chapter_number, ...)` -> list[dict]
- `repo.get_latest_workflow_execution_event(...)` -> dict | None
- `repo.get_workflow_execution_events_since(...)` -> list[dict]

Store 聚合方法：

```python
class ProgressStore(BaseStore):
    def get_project_progress(self, project_id: str) -> dict:
        """聚合：项目级进度快照。
        Returns: {
            "total_token_usage": int,
            "recent_runs": list[dict],        # get_workflow_runs_for_project(limit=10)
            "active_runs": list[dict],         # recover_active_workflow_runs_for_chapter 全项目
            "failed_run_count_recent": int,    # count_recent_failed_workflow_runs
        }
        """

    def get_chapter_workflow_status(self, project_id: str, chapter_number: int) -> dict:
        """聚合：单章工作流状态。
        Returns: {
            "retry_count": int,                # get_chapter_retry_count
            "total_retry_count": int,          # get_chapter_total_retry_count
            "failed_runs_recent": int,         # count_recent_failed_workflow_runs
            "reset_marker": str | None,        # get_latest_chapter_reset_marker
            "latest_event": dict | None,       # get_latest_workflow_execution_event
        }
        """

    def get_recent_events(self, project_id: str, limit: int = 20) -> list[dict]:
        """聚合：最近执行事件。封装 get_workflow_execution_events。"""

    def get_active_runs(self, project_id: str) -> list[dict]:
        """聚合：活跃工作流运行。封装 recover_active_workflow_runs_for_chapter。"""
```

**N+1 风险**：低。各方法独立查询，无循环嵌套。`get_project_progress` 发 4 次查询（可接受，均为单表索引查询）。

class DraftStore(BaseStore):

    def get_draft_history(self, project_id: str, chapter_number: int) -> list[dict]:
        """聚合：草稿历史。封装 list_chapter_versions。"""

    def get_chapter_full_context(self, project_id: str, chapter_number: int) -> dict | None:

- `repo.list_memory_items_by_project(project_id, ...)` -> list[dict]（memory_update）

Store 聚合方法：

```python
class WorldStore(BaseStore):
    def get_world_state(self, project_id: str) -> dict:
        """聚合：项目世界状态全貌。
        Returns: {
            "facts": list[dict],              # list_story_facts
            "fact_index": list[dict],         # list_story_fact_index（轻量索引）
            "active_plot_holes": list[dict],  # list_plot_holes(status="planted")
            "resolved_plot_holes": list[dict],# list_plot_holes(status="resolved")
            "memories": list[dict],           # list_for_project(enabled_only=True)
        }
        """

    def get_active_plot_holes(self, project_id: str) -> list[dict]:
        """聚合：活跃伏笔。封装 list_plot_holes(status="planted")。"""

    def get_facts_by_type(self, project_id: str, fact_type: str) -> list[dict]:
        """聚合：按类型查事实。封装 list_story_facts(type_filter)。"""

    def get_recent_memories(self, project_id: str, limit: int = 20) -> list[dict]:
        """聚合：最近记忆。封装 list_for_project + 切片 limit。"""

    def get_fact_timeline(self, project_id: str) -> list[dict]:
        """聚合：事实事件时间线。封装 list_fact_events。"""
```

**N+1 风险**：中。`get_world_state` 发 6 次查询。`list_story_facts` + `list_story_fact_index` 有重叠数据（v6.10.15 已优化为分层），Store 层应优先用 `list_story_fact_index`（轻量）+ 按需 `list_story_facts_tiered`，避免全量加载。

## 4. 性能基准测试方案

```python
# tests/test_v61019_store_benchmark.py

import time
from novel_factory.stores import ProgressStore
from novel_factory.db.repository import Repository

def test_progress_store_overhead(benchmark_db):
    """Store 聚合查询 vs 手动多次 Repository 查询，开销 <= 1.5x。"""
    repo = Repository(benchmark_db)
    store = ProgressStore(repo)

    # 手动基线
    t0 = time.perf_counter()
    _ = repo.get_workflow_runs_for_project("demo", limit=10)
    _ = repo.count_recent_failed_workflow_runs("demo", 1)
    _ = repo.get_project_workflow_token_total("demo")
    manual_time = time.perf_counter() - t0

    # Store 聚合
    t0 = time.perf_counter()
    _ = store.get_project_progress("demo")
    store_time = time.perf_counter() - t0

    assert store_time <= manual_time * 1.5, f"Store overhead too high: {store_time:.3f} vs {manual_time:.3f}"
```

### N+1 风险评估矩阵

| Store | 聚合方法 | 查询次数 | 风险 | 缓解 |
|-------|---------|---------|------|------|
| ProgressStore | get_project_progress | 4 | 低 | 各查询独立，单表索引 |
| ProgressStore | get_chapter_workflow_status | 5 | 低 | 同上 |
| DraftStore | get_chapter_full_context | 5 | 低-中 | 均单行查询 |
| DraftStore | get_latest_draft | 2 | 低 | 可后续优化为单查询 |
| WorldStore | get_world_state | 6 | 中 | 优先用 index 而非全量 facts |
| WorldStore | get_fact_timeline | 1 | 低 | 单查询 |

## 5. 双轨迁移策略

### Phase A (v6.10.19)
- 实现 BaseStore + ProgressStore + DraftStore + WorldStore
- 性能基准测试
- 选择 1-2 个低风险只读调用方迁移验证（如 API 辅助函数）

### Phase B (v6.11.0)
- 实现剩余 5 个 Store
- 迁移 api/routes/ 只读查询

### Phase C (v6.11.0+)
- 迁移 agents/ 调用方
- LangGraph workflow/runner.py 保持直接用 Repository（避免抽象层干扰工作流引擎）

### 迁移原则
- 新代码优先用 Store 聚合查询
- 旧代码不强制迁移，渐进式
- 写入操作继续用 `store.repo.<write_method>()`
- workflow/runner.py 不迁移（规划文档明确要求）
